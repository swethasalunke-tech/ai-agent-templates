# Data Explorer Agent

An agent that accepts natural language questions about a product metrics database, translates them to SQL, runs the queries, and interprets the results — iterating if the first query comes back empty or ambiguous.

This template demonstrates how to give an agent read-only database access and let it self-correct its queries before presenting an answer.

## What it does

1. Receives a plain-English question as a command-line argument.
2. Calls `get_schema` if it needs to verify column names.
3. Calls `run_sql_query` with a generated SELECT statement.
4. If the result is empty or unclear, it revises the query and tries again.
5. Interprets the data in plain language once it has a useful result.

## Database

The sample database (`sample.db`) contains four tables of fictional product data:

- `users` — 15 accounts across multiple plans (free, starter, pro, enterprise) and countries
- `events` — 20 usage events (page views, exports, API calls, feature usage, upgrades)
- `revenue` — monthly revenue records by user and plan
- `features` — 10 product features with launch date, status, and owner team

- Python 3.10 or later
- An Anthropic API key

```bash
export ANTHROPIC_API_KEY=your_key_here

```

```bash

python agent.py "Which country has the most active pro users?"
python agent.py "What is the total revenue for March 2024?"
python agent.py "Which features are still in beta or alpha?"
python agent.py  # runs the default demo question
```

## Sample output

Question: `What are the top three most-used product features, and which team owns each one?`

The agent didn't stop at the obvious query. It first checked `get_schema` for `events` and `features`, ran a query against `feature_used` events and found only 2 features tracked that way (`dark_mode`, `bulk_assign`, 2 uses each). Recognizing that `api_call` and `export_pdf` events also represent real feature usage (of `api_v2` and `pdf_export` respectively), it broadened the query with a `UNION ALL` across all three event types before joining to `features` for the owning team:

```sql
SELECT feature_name, usage_count, f.owner_team
FROM (
    SELECT json_extract(properties, '$.feature') AS feature_name, COUNT(*) AS usage_count
    FROM events WHERE event_name = 'feature_used'
    GROUP BY json_extract(properties, '$.feature')
    UNION ALL
    SELECT 'api_v2', COUNT(*) FROM events WHERE event_name = 'api_call'
    UNION ALL
    SELECT 'pdf_export', COUNT(*) FROM events WHERE event_name = 'export_pdf'
) AS feature_usage
LEFT JOIN features f ON feature_usage.feature_name = f.name
ORDER BY usage_count DESC
LIMIT 3
```

| Rank | Feature | Usage Count | Owning Team |
|---|---|---|---|
| 1 | API v2 | 4 | Engineering |
| 2 | PDF Export | 3 | Engineering |
| 3 | Bulk Assign | 2 | Product |

Answer: *"API v2 is the most-used feature, owned by the Engineering team, with 4 recorded uses. PDF Export comes in second, also owned by Engineering, with 3 uses. Bulk Assign rounds out the top three, owned by the Product team, with 2 uses."*

Completed in 5 iterations: schema checks, an initial narrow query, a broadening query across all event types, and the final combined query.
